Competitor collection status

A case file is only as good as the dates on its evidence. For each competitor app, four status reads tell you where collection stands: the last paid-ad refresh you asked for, the ASO collection, the technology observation, and the data requests you filed. Paste them here and see which apps are current, which are stale, which are still running and which were never collected, with the refresh requests worth sending. Paste an earlier report too and it lists what changed. Nothing leaves your browser; this page never calls the API.

Where to get the JSON

The reads come from PeekPanda, an iOS competitor catalogue where every app has a case file of dated, stored evidence. Each read is one call from your plan's daily API and MCP allowance, scope context:read, and none of them starts collection:

for p in paid-ads/refresh aso/collection technology data-requests; do
  curl --get "https://api.peekpanda.com/v1/competitors/ios/493145008/$p" \
    --header "Authorization: Bearer $PEEKPANDA_TOKEN"
done

Over MCP they are get_app with actions ad_refresh_status, aso_status, technology and data_requests. From technology this page uses only the documented status and date fields. Freshness and source dates explains why a fresh answer about an old observation is still old. The command-line version on GitHub reads a whole list file, keeps a weekly diff, fails a CI job when something is stale and posts to Slack or Discord.
